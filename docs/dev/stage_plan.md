# 三舞台（神/人/妖）战斗场景总体规划

> 状态：**现行计划**（2026-07-24 立项，后续舞台/场景工作一律沿用本文档）。
> 目标：战斗背景从静态棋盘升级为「同一画风、动静结合、含标志神像交互」的
> 三套舞台，总成本 ≤ ¥2000（不含音效）。
> 相关：客户端资源规范 `../client/assets_upload_guide.md`、
> 阵营视觉 `../client/faction_style.md`、机制注册表范式 `../mechanics/formations.md`。

## 一、根本原则（不可违背）

1. **同一画风铁律**：一个舞台内所有元素（背景/道具/神像/粒子特效/交互动画）
   必须同一形状语言与色板；三舞台间共享同一世界观质感、只换色温与题材。
2. **先动态后静态的工序**（品质感保证的唯一正确顺序）：
   - 特效包的风格改不动，AI 出图的风格随便调 → **先买定特效包**；
   - 从特效包截图提炼「风格卡」（色板色值/光感软硬/饱和度档位）；
   - AI 出全部静态资源时以特效截图为风格参考（垫图），确保发光件与粒子同源；
   - 最后全局色调分级（color grading）压平残差。
3. **神像加成 = 结算机制，必须 core 侧**：客户端零结算，只播交互动画。
   实现同构于阵型系统（`battle/formations.py` 注册表范式）。
4. 舞台机制对契约只做**加法演进**（新增可选字段/新增状态 id，不改已有语义）。

## 二、三舞台提案

阵营映射：神=奥林匹斯；人=英雄；妖=海域+冥界合并（视觉基因同源：深水/幽绿/非人）。

### 舞台一 · 神「奥林匹斯山巅」

- **基调**：白金大理石 + 深蓝夜空 + 云海（冷色、圣洁）。
- **标志神像**：**赫拉巨像**（推荐；有神格且不在 32 将池，避免"宙斯在宙斯像下打宙斯"）。
  备选：尼刻（池内，次选）。
- **加成对象与效果**：**神阵营**（faction=olympus）英雄——造成伤害时
  10%（1000 bps）几率**伤害双倍**（整场被动）。
- **交互动画**：神阵营英雄触发双倍 → 赫拉像双目亮金 → 柔光束洒到英雄卡 →
  卡面短暂镀金描边。
- **静态（AI 出）**：全景背景、赫拉像本体+发光层、孔雀浮雕 ×2（赫拉圣物）、
  云海远景层、中央徽记。
- **动态（代码+特效包）**：云海滚动（代码 UV）、徽记呼吸（代码）、
  天空远雷（包内闪电改色）、神像洒光（包内光束）。

### 舞台二 · 人「特洛伊城下角斗场」

- **基调**：青铜 + 砂岩 + 战旗 + 扬尘（暖色，与神舞台冷暖对比）。
- **标志神像**：**阿特拉斯扛天巨像**（推荐；非池内，弓背扛球剪影极具辨识度，
  凡人苦力感配"人定胜天"）。备选：无名斯巴达战士像。
- **加成对象与效果**：**人阵营**（faction=heroes）英雄——释放主动战法时
  8%（800 bps）几率**技能再次释放**（整场被动）。
- **交互动画**：触发再释放 → 天球裂出红光 → 尘土冲击波沿地面推到英雄卡下 →
  卡底裂缝贴花 + 卡牌重震。
- **静态（AI 出）**：角斗场背景、阿特拉斯像+天球发光层、战旗 ×2、砂土质感层。
- **动态（代码+特效包）**：战旗飘动（代码 skew 循环）、扬尘环境粒子、
  冲击波、火把火焰（均包内）。

### 舞台三 · 妖「冥海裂渊」

- **基调**：黑礁石 + 幽绿冥火 + 深海微光生物（最暗；暗场景最遮 AI 素材瑕疵，性价比高）。
- **标志神像**：**克拉肯半沉巨像**（推荐；只露头颅与两条石化触手，海域+冥界通吃）。
  备选：提丰（NPC 首领，留给 PvE，不用）。
- **加成对象与效果**：**妖阵营**（faction=sea/underworld）英雄——施加负面状态时
  10%（1000 bps）几率**持续回合 +1**（整场被动）。
- **交互动画**：触发延时 → 石眼亮绿 → 幽绿暗流从像底涌向英雄卡 → 卡面水波纹（shader 扰动）。
- **静态（AI 出）**：深渊背景、克拉肯像三层（头/触手 ×2）、发光水母远景、冥火火盆。
- **动态（代码+特效包）**：水面焦散（shader 或包）、气泡上升粒子、
  冥火绿焰、暗流水流特效改色（均包内）。

## 三、神像加成机制（core 侧设计）

- `battle/stages.py` 新建注册表 `STAGE_REGISTRY: dict[str, StageDef]`
  （同构 `formations.FORMATION_REGISTRY`）：`stage_id` → 受益阵营判定 +
  整场被动 `StatusDef`。
- 舞台 id 经 `BattleSetup` 元数据传入；每局 game_start 后挂被动
  （接线点同 `_apply_formation_buffs`）。
- **受益判定用现成阵营字段**（`roster.FACTION_OF`，A4 定稿
  olympus/heroes/sea/underworld），不新增字段：
  神舞台惠及 olympus；人舞台惠及 heroes；妖舞台惠及 sea 与 underworld。
- **三舞台效果定数**（bps 写入代码常量）：
  神＝造成伤害 10%（1000 bps）几率伤害双倍；
  人＝主动战法 8%（800 bps）几率再次释放；
  妖＝施加负面状态 10%（1000 bps）几率持续回合 +1。
- 随机判定必须走单一 RNG 流（独立 reason 标签），保证确定性与重放一致。
- 客户端：`StatusPresentationRegistry` 登记三个舞台状态；神像作为 BoardActor，
  触发动画挂状态触发/伤害结算回调。中文名照例双端同步
  （`names.py` ↔ `ChineseNames.cs`）。
- 落地时须新建 `docs/mechanics/stages.md` 并在 mechanics index 登记，
  extension_points.md 追加注册表条目。

## 四、美术风格基准与采购清单（≤¥2000，不含音效；2026-07-24 商店核价）

### 0. 风格基准定论（本节是全项目美术方向的地基，先于一切采购）

- **成品方向：史诗感优先，其次写实精致**（epic > realistic-refined）。
  依据游戏内容：希腊神话神系（宙斯雷霆/波塞冬潮汐/哈迪斯冥域/雅典娜圣盾/
  阿波罗圣光）天然要求庄重、宏大、有神性重量的画面，卡通 Q 版会消解题材本身
  的史诗性；立绘、舞台、特效三者必须同向。
- **单一出品人家族策略**：特效统一从 **kripto289（KriptoFX）** 家族购入——
  该家族即"史诗写实"代表作（写实光效/体积感/屏幕空间贴花，自带音效），
  同作者同代资源天然同风格，是花钱买"统一性"的最稳做法。
- **已购卡通三包的处置（沉没成本，直面它）**：Vefects / Cartoon Coffee /
  四色弹道属卡通系，与成品方向冲突。处置：**战斗高频特效（命中/雷电/弹道/
  斩击）随舞台落地逐步换成 kripto 家族**（variant 引用替换，零代码，见
  assets_upload_guide §二.5）；卡通包降级为快速原型与占位备胎，不再出现在
  成品画面。势能火/柔光等已调校好的 CFXR 件验收时逐个目检，出戏者一并换。
- **AI 静态出图基调随之锁定**：写实厚涂·史诗神话（参考基准：写实浓彩神话
  插画，非赛璐璐非美漫），全部垫 kripto 特效截图与首张定稿全景做双参考。

### 4. 购买红线（沿用 assets_upload_guide §三）

- 本项目是 **URP Universal Renderer（3D 前向）**，**不是** 2D Renderer
  （2026-07-28 核实 `Assets/Settings/{PC,Mobile}_Renderer.asset`＝`UniversalRendererData`；
  舞台是透视长焦立体布景，深度缓冲被 `CardDepthProxy` 与折射/贴花依赖）。
  故采购口径是「支持 URP」而非「支持 2D 管线」；标着 3D-only 的包**不必**因此排除，
  真正的筛选红线是 §四.0 风格与本节其余各条。历史文档里"URP 2D Renderer"的表述已作废；
  依赖场景深度图的屏幕空间方案（Screen Space God Rays 类）兼容风险高，
  光效走 Lumen 网格式方案。Realistic Effects Pack 4 **购后先导 URP patch
  并在 2D 场景实测**（评价区确认 Unity 6.3 + URP 可用），跑不通再退而用
  主包 #1 顶替其位。
- **风格一票否决**：任何新包购前与风格卡比对，卡通/赛璐璐/像素系一律不买，
  哪怕免费；单一家族原则只允许 kripto289 + 风格中性 shader 件破例。
- 用与工程一致的 Unity ID 购买；购入后登记 assets_upload_guide §三 采购表。
- 顺序铁律：**先买 #1 提风格卡，AI 出图全部垫它的截图**；
  #2~#5 到货后统一改色向风格卡对齐。
