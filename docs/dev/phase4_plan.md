## 〇、验收口径与总原则

- 验收口径（任务书原话）：**赛前像配将、局中像主教练、战斗像神话动作片**。
- 架构原则：绝大多数新机制 = 新状态/新钩子 + 契约加法演进；仅两处新增架构面
——经理人逐回合快照续算（P4-C）与势能→表现/音乐调度（P4-B）。不动 5 层框架。
- **可扩展可维护通则**（本轮全部新机制一体适用）：新增内容一律「注册表驱动」
  ——势能加分表、trait→单挑行为表、战术定义表、势能表现分级表、溢出演出 key、
  BGM 层映射全部做成配置注册（服务端 dict/客户端 SO），加条目即扩展，
  禁止在引擎/Runner 主流程写死特例（global_rules 既有红线的延伸）。
- 三批次 **P4-A（服务端）→ P4-B（客户端）→ P4-C（经理人）**，
每批独立可验收可上线；A 不阻塞现网，C 风险最高放最后。
- 付费资源采购极度克制：新演出优先复用已购三包 + 程序化占位。

### B3 附：BGM 素材路线（低成本高品质，按优先级）

- **红线：禁止使用著名 BGM 的 AI 变调/改编**。对受版权保护乐曲变调仍属
衍生作品，全球上线商业项目构成侵权（旋律相似度可诉，AI 加工不豁免）。
- **路线 1（主路线，≈0 成本）**：AI 生成 + 开源拆 stem——Suno/Udio 付费档
生成史诗管弦战斗曲（付费订阅自带商用授权，可无限试稿选优），选定后用
开源 **Demucs**（Meta，本地运行）拆成 鼓/贝斯/旋律/其他 4 stem，
正好对应分层结构。品质上限高于小额委托。
- **路线 2（真·著名级品质）**：公版古典管弦（希腊神话适配度高）——
Musopen 等站取 **作曲公版且录音也是 CC0/PD** 的版本（作曲公版≠录音公版，
录音授权必须单独核验），同样 Demucs 拆层。代价：曲目受限、辨识度是借来的。
- **路线 3（保底）**：CC-BY 游戏音乐库（Kevin MacLeod/incompetech、
OpenGameArt 的 adaptive/loop 类），署名即可商用，部分作者直接提供 stem。
- 后处理：Demucs 拆出的 stem 需在 DAW（Audacity 免费）裁齐循环点与小节；
各层同 BPM 同长度是硬要求。素材与授权证明登记进
`docs/client/assets_upload_guide.md` 采购登记表。
- 原「委托音乐人出 4 stem（¥300~800）」降级为备选：仅当上述路线成品
均不满意时再走。

## 五、P4-C 经理人批（架构项，单独立项，最后做）

### 1. 交互模型（定案）

- **战术区**：屏幕**左侧竖直区域**常驻战术选项图标（不弹窗、不暂停播放）。
- **预设**：开战前每方配置预设战术；开战后不操作则整局走预设。
- **变更**：玩家任意时刻点击新战术并「应用」→ **下一回合开始生效**
  （最早也是第 2 回合生效——第 1 回合必然走预设）；一局每方**最多变更 2 次**；
  应用后按钮进入冷却态并显示「第 N 回合生效」。
- **战术内容**：只含整体倾向与额外加成（§二4 首发三项：集火/保护/攻守滑杆），
  实现为下一回合起施加的加成状态与权重偏置，**不涉及机制大改**；
  新战术=新增一条战术定义（状态组合+偏置参数）注册进战术表，可持续扩展。
- **不再设置快进/跳过选项**（对局播放）：战术窗口必须真实经过，
  快进会跳过决策时机。回放/客服工具（replay_report、高光回放）不受此限。

### 2. 服务端改造：逐回合战报能力（核心架构项）

- **开战流程**：客户端发战斗信号（含双方 setup+预设战术）→ 服务器一次性
  生成**预设战术下的全局完整战报**下发 → 客户端开始播放。
- **回合快照**：引擎在每个 round_start 边界产出**可续算快照**
  （全部战时状态/伪随机记账/RNG 状态/势能/延迟与准备登记的确定性序列化）。
  实现为 `SeriesEngine` 的 snapshot/restore 原语——这是本批最大的工程点，
  快照必须完备到「从第 N 回合续算 ≡ 从头模拟」逐字节等价（关键回归测试）。
- **战术变更**：任一方在第 N 回合内发出变更信号 → 服务器取第 N+1 回合
  边界快照，注入新战术，**即时重算 N+1 回合至战斗结束的完整战报**，
  以「替换段」下发（`tactic_applied` 事件在 N+1 回合头部记录变更内容）。
  双方同回合都变更时合并注入一次重算（按队伍序确定注入顺序）。
- **确定性与重放**：整局由 (seed, setup, 预设战术, 变更序列[回合号+内容])
  完全决定；重放工具按同一序列重跑必须逐字节一致；golden 新增
  「中途变更战术」用例。
- **断线兜底**：客户端持有的战报永远是「到战斗结束的完整版」，
  断线即按手头版本播放至结束，结果以服务器最终版为准（重连后校正）。

### 3. 客户端改造：逐回合修正播放

- 播放器支持**替换未播放段**：收到修正战报后，定位当前播放回合，
  丢弃本地 N+1 回合起的旧事件组、无缝接入新事件组（镜像状态在回合边界
  天然一致，因为 N+1 之前的事件两版完全相同——服务器只从边界起重算）。
- 左侧战术栏 UI：竖直图标列 + 当前生效战术高亮 + 剩余变更次数 +
  「第 N 回合生效」倒计标。`tactic_applied` 事件播报横幅（复用非阻塞通道）。
- 对手为异步托管时，其预设/托管策略变更同样以修正战报形式到达，
  客户端处理逻辑与己方变更完全一致（同一条替换段通道）。

### 4. C 批验收

- 空变更局：分段快照续算与一次性模拟**逐字节一致**（第一条测试先写）。
- 变更局：任意回合注入战术 → 重算段与直接以该序列全程模拟逐字节一致；
  客户端替换段播放无缝（回合边界无重播/漏播）。
- 一局 2 次变更上限、最早第 2 回合生效、断线播完兜底逐条走查。
- 契约（`tactic_applied`）、机制文档（新增 `docs/mechanics/manager_tactics.md`）
  与 schema 同步。

  以 round_start seq 为唯一切点，边界一致性做自动化断言。
