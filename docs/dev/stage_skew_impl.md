# 可复用舞台构图系统（拧镜头 × 三舞台 + 全屏天幕屏 + 3D 道具）

> 状态：**现行计划**（2026-07-29 立项，同日三修定稿：由"转场地"改为
> **拧相机滚转**实现三构图；天幕屏永远占满全屏，不再做云海崖缘/渊壁）。
> 目标：相机滚转一个角度 + 每舞台一套资源 = 三种构图；
> 战斗逻辑/事件契约/结算 **零改动**；回放入口先传舞台 id 再初始化。
> 上位规划：[stage_plan.md](stage_plan.md)；相机与几何权威：
> [../client/arena_stage.md](../client/arena_stage.md)（红线修订见 §二c）；
> 站位权威：[../client/battlefield_layout.md](../client/battlefield_layout.md)。

## 〇、一句话方案

场地几何完全不动（`RotationDeg` 恒 0、站位/微调圆/击退原样），**只拧相机
滚转角（roll）**；背景改为**挂在相机下的全屏天幕屏**（不透明，永远盖满
视野，跟随滚转，不存在露黑角）；地面从"铺满屏幕的板"改为"浮在天幕上的
有限高台"。三舞台差异＝一个 roll 角 + 一套资源：

| 舞台 | 相机 roll | 屏幕构图 | 资源 |
|---|---|---|---|
| 人 · 特洛伊 | **0°** | 现行大正面：A 下 B 上，隔离带水平 | 基准套：重绘地面贴图 + 3D 道具 + 天幕 |
| 神 · 奥林匹斯 | **≈−30°（逆时针拧）** | 隔离带呈 30° 斜线（左上→右下），A 左下 B 右上 | **直接复用人全套**（后续最多换一张天幕图） |
| 妖 · 冥界 | **90°** | 隔离带竖直，A 左 B 右完全对称对峙 | 地面/氛围物/天幕整体重换；**卡牌与跳字反拧回正**（§三） |

## 〇b、可行性与建议（2026-07-29 评估结论）

**可行，建议做；是三版方案里最便宜的一版。**

1. **roll 是纯图像旋转，零透视畸变**：透视由俯角与焦距决定，roll 只把成像
   整体转一个角，两队梯形形状不变——神舞台担心的"小畸变"实际不存在。
   屏幕夹角＝roll 角，**精确相等**，不再需要 `atan(tanθ·sinp)` 换算。
2. **神舞台边际成本≈0**：一行 roll + 复用人全套资源，白得一个斜视构图。
3. **场地几何零改动**：不转 `RotationDeg`，就不碰 `StanceHalfDepth` 修正、
   不碰对齐底稿角度、贴图里的隔离带照旧画水平/竖直参考——出图难度下降。
4. **全屏天幕屏消掉了滚转的历史禁令前提**（露黑角），见 §二c。

**风险最大点仍是妖 90°**，但性质变了：不是遮挡而是**装不下**——横屏视野
垂直方向本来就矮，90° 拧过来后场地 12 单位的宽要塞进屏幕竖向，卡必然缩小；
外加"世界拧 90° 而卡反拧回正"的视觉自洽问题（§四.9）。
**实施第一步就摆 90° 定生死**；不成立则妖退 −60°~−45° 深斜视，机制不变。

**明确不做**：相机偏航（yaw，真畸变+两队不对称，维持禁止）、转场地
（`RotationDeg` 保持 0）、云海崖缘/渊壁实体（天幕屏占满即背景，台缘只做
alpha 渐隐融进天幕）、视频/GIF 天空（§三c）。

## 一、为什么这套便宜（决定成本的三条）

1. **roll 角每舞台固定** → 构图斜线由相机免费产生，贴图按水平/竖直画，
   近远渐变照旧烤死，运行期零计算。
2. **天幕屏挂相机**（相机子物体、远端全屏 Quad、不透明 Unlit）→ 永远盖满
   视野、跟随滚转、零对缝零取尺，比任何世界摆放都简单。
3. **神舞台资源全复用**：三套构图只需两套地面资源（人基准 + 妖重制）。

## 二、roll 角与几何

- 屏幕夹角＝roll 角（精确）。人 0° / 神 −30°（逆时针拧 → 画面顺时针转 →
  隔离带左上→右下、A 左下 B 右上）/ 妖 90°（隔离带竖直、A 左 B 右）。
- 俯角 `PilotPitchDeg` 维持现行 35°，**本方案不动它**（后续想提立绘可读性
  再单独评估 45°，与本方案解耦）。
- roll 后可视地面区域是旋转矩形：安全区/摆位校验要按"旋转后的视口"重算
  （§五 `RecalcFromCamera` 修订）；90° 时等效于横竖视野互换，
  可视宽度从 W 变为 H——妖舞台卡尺寸压力的来源。

### 二b、横竖屏支持（2026-07-29 追加：能做到，机制免费、UI 另计）

- **战斗逻辑零涉及**：core 结算与事件流是纯世界空间，不知屏幕存在。
- **舞台层天然支持**：roll 机制就是竖屏适配工具——妖的 90° 布局即竖屏
  构图（场地 12 宽拧到竖向长轴，投影深度 ≈6 落窄轴，正好塞进 9:16）。
  `StageCompositionConfig` 增加朝向维度：按 **舞台 × 横/竖** 查
  roll 角与 `CardCounterRollDeg`，同一套代码；参考初值：
  横屏＝§〇表；竖屏＝人/神 roll 90°（±30° 叠加可选）、妖 roll 0°。
- **天幕屏/高台/反拧组件全部朝向无关**：屏挂相机自动盖满；高台浮在天幕上
  无露边；跳字/血条反拧对任意 roll 生效。
- **`RecalcFromCamera` 按 roll 后视口反算**（§五既有条目）天然覆盖
  aspect<1；验收矩阵扩为 4:3 / 21:9 / 9:16 / 3:4 四点。
- **真实成本在 HUD/UI**：手牌/按钮/结算 Canvas 需横竖两套锚点，cut-in
  横幅与单挑取景需竖屏变体——常规 UI 适配工作，独立于本方案排期。
- **局中热切换**：朝向变化时重建构图（相机 roll + 反拧角 + 安全区重算）；
  播放单元在飞的帧允许一帧内瞬移完成重排（与分辨率热切换同一策略）。

### 二c、滚转红线修订（需同步 arena_stage.md §五）

原禁令"相机禁止偏航/滚转"的滚转半条，成立前提是**地面必须正好铺满屏幕**
（一转就露黑角/地台一头高一头低无法对缝）。本方案地面改为有限高台、
背景为挂相机的全屏天幕屏，前提消失，**滚转解禁**；偏航（yaw）禁令保留。
实施步 4 时同步修订 `docs/client/arena_stage.md`，注明解禁条件。

## 三、反拧回正（妖 90° 的可读性方案）与天幕动态

### 三a、哪些东西反拧、拧多少

世界被拧 90° 后，为保可读性，**屏幕朝向敏感件**绕相机前向轴反拧回正：

| 对象 | 处理 | 说明 |
|---|---|---|
| 跳字/飘字 | **全舞台永远反拧到屏幕正向**（含神 −30°） | 本来就是即时信息，任何角度都不该歪 |
| 血条/势能条/气泡 | 同上，反拧到屏幕正向 | 挂点仍跟卡，只转朝向 |
| 卡牌本体（妖） | 反拧 **60°~90° 可调**（`CardCounterRollDeg`） | 用户定调"可以扭转一定角度"；从 90°（完全回正）起调，若与地面/影子朝向违和再退到部分反拧 |
| 卡牌本体（人/神） | 不反拧 | 神 30° 倾斜为构图的一部分，已接受 |
| 罩身/光环/裂地/弹道 | **不反拧** | 世界空间演出，跟世界一起拧才自洽 |
| cut-in / 单挑聚光 | 不处理 | cut-in 面挂相机子物体，天然跟滚转、屏幕端正（P-64 结构红利） |
| HUD/结算 UI | 不处理 | 屏幕空间 Canvas，与相机姿态无关 |

### 三b、防穿帮（比前版大幅简化，剩三条）

> 天幕屏本体的完整方案（几何/渲染/动态/画质档/迁移/坑位）单列：
> **[stage_backdrop.md](stage_backdrop.md)**。

1. 天幕屏挂相机、尺寸按远端视锥截面 ×1.1 → 任何滚转/运镜都不露边。
2. 高台边缘一圈 alpha 渐隐 + 台缘雾光（画进地面贴图），融进天幕色温；
   地面贴图外缘 20% 渐变到天幕底色（大气缝合）。
3. 台缘可散少量 3D 道具压边（断柱/礁岩），非必需。

### 三c、天空"动态"实现选型（结论：UV 滚动 shader，不用视频/动图）

| 方案 | 成本 | 判断 |
|---|---|---|
| **双层 UV 滚动 + 视差**（推荐） | 一个 Unlit 变体 shader；零解码、无限循环、显存＝两张贴图 | ⭐ 远层不透明慢速；近层带 alpha 快一档、**面积 ≤1/3 屏**；可加极简 UV 扰动做涌动 |
| 序列帧 flipbook | 显存大 | 备选：仅局部小区域（冥火、渊光脉动） |
| 视频 VideoPlayer | 每帧硬解码耗电、循环接缝、RenderTexture 显存、双端编码兼容 | ✗ 常驻背景不用 |
| GIF | Unity 不原生支持 | ✗ |

### 三d、妖舞台手机端负载账（结论：负载≈人舞台，可行）

- 相机 roll：改一次 `transform.rotation`，**零每帧成本**。
- 反拧回正：每卡/每飘字一个四元数乘法（LateUpdate），六卡 + 少量飘字，
  **微不足道**；跳字本可做成纯 billboard，一次实现全舞台受益。
- 全屏天幕远层：**不透明单 draw**，替代原天空板，不新增；近层动态受
  §三c 面积纪律约束。地面高台不再铺满屏，**不透明像素反而变少**。
- 无新增相机、无 RenderTexture、无后处理。⇒ 与人舞台同一档，
  `FrameSpikeProbe` 验收即可。**妖的真实风险在布局（§〇b），不在性能。**

## 四、硬约束与坑位清单

1. **道具会真实遮挡卡牌**。卡牌是透明队列 Sprite（`ZWrite Off` 但 `ZTest LEqual`），
   不透明 mesh 在卡前面就会挡卡，sortingOrder 救不了。摆位纪律：道具屏幕
   投影不得与六个站位卡包围盒相交，每舞台按 §八目检（含 4:3 / 21:9）。
2. **贴图隔离带与代码几何对齐**：出图垫对齐底稿（调试网格导出格心/隔离带
   线框）。roll 方案下底稿不带斜角（斜线由相机产生），难度低于前版。
3. **站位区离台缘留余量**：命中裂地直径最大卡宽×2.25（档 3 拉满），
   厂包深度贴花在台外无表面会拉伸；按此留余量再加一格。
4. **全屏半透明动态层禁令**（§三c 面积纪律；vfx_mobile_budget 第一死因）。
5. **跳字/血条反拧后的挂点漂移**：反拧只改朝向不改挂点；但 90° 下血条在
   卡"上方"意味着屏幕左/右侧，需按屏幕方向重算偏移（跟随反拧一起处理）。
6. **妖 90° 视野互换**：可视宽度变为屏高，场地 12 宽 vs 屏幕竖向 ——
   卡尺寸缩小不可避免，`CardScaleBoost` 只能部分补偿；步 1 实测定生死。
7. **卡反拧 vs 世界拧 90° 的自洽**：卡回正后，其投影圆/影子/罩身仍按世界
   方向呈现（横着的椭圆逻辑变成竖着），可能读作"卡浮在侧向地面上"。
   目检项；违和则降反拧角（60°~75°）折中。
8. **`RecalcFromCamera` 安全区**：现按无滚转视口反算地面可视矩形与卡尺，
   需按 roll 旋转视口重算（90° 即宽高互换）。漏改的症状＝卡出屏或全场偏小。
9. **神 −30° 的卡面倾斜**：立绘/血条歪 30°（血条跳字已反拧，只剩立绘）。
   已定调接受；上线前 A/B 目检一次确认阅读负担可接受。
10. **3D 包是 PBR，本工程无光照环境**（地面 `URP/Unlit`、实时阴影全关）。
    一律改 Unlit 或最简 Lit + 关阴影 + 光烤进 albedo；4K 贴图导入 Max Size
    压 1024；无 LOD 的包只用作远中景单件。
11. **单挑/cut-in 运镜叠加 roll**：`StageCameraRig` 的推近若直接写
    rotation 会抹掉 roll，改为在基准姿态（含 roll）上叠加；验收逐舞台过
    一遍单挑与 cut-in（P-64/P-65 复查）。
