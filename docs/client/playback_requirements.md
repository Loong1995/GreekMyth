# 战斗播放逻辑要求（行为规格书 v1.0，2026-07-23）

> 本文是**客户端战报播放系统的唯一行为规格**：任何实现（含重构后代码）必须满足
> 本文全部条款；条款冲突时以 `docs/discipline/global_rules.md` 为最高裁决。
> 架构如何满足这些要求见 [architecture.md](architecture.md)。
> 编号规则：R-x.y（Requirement），验收时逐条对照。

## 〇、输入与权威性

- **R-0.1 唯一输入**：一份完整战报 JSON（schema ≥1.4.1，`docs/schema/`）。
  客户端不访问任何其他战斗数据源。
- **R-0.2 零结算**：兵力/状态/属性/胜负一律取事件 payload 权威值
  （`troops.troops_after` 等）；禁止任何数值推算、插值兜底、客户端补账。
- **R-0.3 向前兼容**：未知事件 `type`、未知 payload 字段必须跳过并单次告警，
  播放继续，不得中断或报错弹窗。
- **R-0.4 幂等落账**：同一事件被"静默落账"与"演出结算"两条路径先后触达时，
  最终视图状态必须一致（以权威值刷账天然幂等，不允许增量加减）。

## 一、播放生命周期（状态机）

- **R-1.1 状态全集**：`Idle → Building → Prewarming → Playing → Finished`，
  加中断迁移：`任意态 → 硬停止 →（Idle | Finished）`。硬停止（`HardStop()`）
  为同步原子操作，语义等价于 Stopping 过渡态，不单独入枚举。任何公开操作
  （播放/重播/跳过/高光/回配阵）都必须表达为该状态机上的合法迁移。
- **R-1.2 硬停止**：执行硬停止时必须一次性完成——
  ① 停编排协程；② 杀所有播放期 tween（含单位位移/弹道/闪烁）；
  ③ 清飞行中特效/飘字/气泡/cut-in/横幅/相机震动；④ 停战斗 BGM。
  停止后场上不得残留任何仍在推进的动画（**重播叠影为 P0 级 bug**）。
- **R-1.3 重播**：重播 = 硬停止 + 全量重建世界 + 从头播放。势能镜像、光环、
  cut-in 组去重、单位 RestPosition 等一切会话内状态必须归零。
- **R-1.4 跳到结尾**：硬停止在飞演出后，把剩余事件按原始 seq 序静默落账，
  终态（兵力/阵亡/状态图标）必须与正常播完一致；是否弹结算面板由调用方
  显式指定（回配阵路径不弹）。
- **R-1.5 回配阵（Teardown）**：硬停止 + 销毁棋盘/单位/背景/滤镜等全部战场
  可视 + 清空会话引用。之后再次播放必须与首次播放行为一致（无残留态）。
- **R-1.6 高光回放**：等价于"带 [startSeq, endSeq) 窗口的重播"：窗前事件
  静默落账、窗内正常演出；复用主播放循环，不允许单独一套演出代码。
- **R-1.7 并发保护**：任何时刻最多存在一条播放会话；公开入口连点/竞态调用
  不得产生第二条会话（由状态机迁移守卫，而非调用方自觉）。

## 二、播放单元（EventGroup）

- **R-2.1 全量聚合**：按 `group_id` 用字典聚合非连续段（组序 = 首次出现序）。
  禁止只合并连续段（坑 P-03：群攻会被响应 tick 插队切碎）。
- **R-2.2 单元占轨规则**：只有行动类组（主动/普攻/追击/状态触发/单挑）占用
  时间轴；节点/状态变更/阵亡/记账组即时落账零阻塞；`ParallelWithNext`
  组与下一组并行。
- **R-2.3 组内完整性**：一个单元演出结束时，组内**所有**事件必须已落账
  （伤害/治疗走演出结算，其余副事件走统一落账），不允许漏账（坑 P-04）。
- **R-2.4 拆组保 Root**：任何管线拆分不得让子事件成为无 Root 组
  （坑 P-17）；拆出的组必须有明确 `GroupKind`。
- **R-2.5 管线加工次序**（语义层面，实现可合并步骤但不得改变可观测结果）：
  借刀按段拆分回插原生序 → 响应 status_tick 摘出后置 → **批次触发合并**
  → 台词抽为独占组 → 特殊标记（如傲慢贯穿）→ 节点并行标记 → cut-in 注记。
- **R-2.8 同批次同步播**（2026-07-28）：同一次行动引发的同状态触发并成
  **一个**播放单元（群攻打三人 → 三人的落雷一起劈）。批次＝`EventGroup.BatchId`
  （沿 parent 上溯，止于最近的行动组）；能不能并由**服务端定义期标签**裁决
  （`status_catalog` 的 `simultaneous` / `sequential`，schema 1.5.2），
  客户端不猜。战法侧同理：`skill_catalog.tags` 的 `per_target` / `simultaneous`
  是「群攻＝一个单元齐射」的特殊配置口子。
- **R-2.7 编译一次、运行只读**（2026-07-27）：全部管线加工与编译期决策
  （cut-in 注记等）在开播前由 `PlaybackCompiler.Compile` 一次完成；主循环/
  高光/任何消费方读同一份 `CompiledPlayback`，禁止播放期再跑管线或推断语义。
  分类优先读战报头 `skill_catalog`（schema 1.5.0），无目录回落启发式并告警。
  权威 [playback_script.md](playback_script.md)。
- **R-2.6 响应序**：响应类单元的相对播放序必须等于事件流 seq 序
  （先守后攻、他人施加先于自身，坑 P-15/P-16），客户端不得二次重排。

## 三、演出模板族（每类单元怎么演）

- **R-3.1 模板选择**：三级配置（特殊配置 → 组默认 → 全默认）决定模板与资源
  key；无配置也必须能播出（占位回退）。`Auto` 推断规则：普攻/单体追击 →
  Melee；互异目标 ≥2 → AoeCenter；否则 PerSegment。
- **R-3.2 Melee**：施法者突进至目标近身（瞄目标当前休息点）→ 命中帧目标身上
  闪斩击（普攻 1.0 / 追击与状态触发 1.5，均乘 profile 缩放）→ 逐段结算 →
  回位。回位与受击顿挫结束都要重采样休息点（Home 中心、边长=卡宽/4 方形）。
- **R-3.3 AoeCenter**：施法者移动至棋盘中心 → N 道弹道错峰起飞同帧抵达 →
  同帧结算全部伤害 → 回位。整战法一个单元（一次 N 道光）。
- **R-3.4 PerSegment**：逐段：弹道飞行（可见）→ 结算；段间不垫定格。
- **R-3.5 RemoteStrike**：施法者不位移；目标头顶头像标 + 自上而下贯穿
  （无 ProjectileKey → 程序化竖雷；有 key → VFX 弹道）→ 同帧结算。
- **R-3.6 OracleAura**：施法者前摇 → 组内状态一次性落账（同帧挂光环）
  + 可选整盘滤镜。
- **R-3.7 Duel**：压暗渐变（微灰 ~78%，覆盖全场无关武将）→ 号角 → 叫阵气泡 →
  （拒战｜应战 → 全屏裂缝交错 cut-in × clash_cutins → 胜者）→ 恢复渐变。
  单挑台词按时点在单元内播，不抽 TraitLine（坑 P-22）。
- **R-3.8 纯治疗组**：无伤害段的组不得走 Melee/CastKey；必须逐条 `SettleHeal`
  （绿字治疗量 + 治疗特效 + 刷兵力）；圣盾重击回血另闪 `icon_aegis_heal`。
- **R-3.9 格挡/反弹**：`mitigation=block/reflect` 时出击动画完整播放（不省略
  突进），受击方轻顿挫 + 卡面中央渐变闪 `icon_block`/`icon_aegis`；伤害 0 飘字照出。
- **R-3.10 TraitLine**：独占时间轴（气泡时长内阻塞），播完与邻组无缝衔接
  （不加单元停顿）；台词时长以服务返回/文本长度规则为准（坑 P-18/P-19）。

## 四、时间轴与节奏

- **R-4.1 零死帧**：所有 yield 等待必须对应一段正在播放的可见动画（位移 tween
  / 弹道飞行 / 命中·治疗特效可见窗）；纯定格只允许出现在单挑横幅。
- **R-4.2 节奏参数**：行动窗停顿（ActionPause）、单元停顿（GroupPause）、全局
  时长倍率（DurationMul）、速度（Speed）为可调参数；TraitLine 邻接不加单元停顿。
- **R-4.3 连发**：`burst_no≥2` 归类主动（非追击）、同模板、节拍加速 + "连发×N"
  角标；连发不重复满档 cut-in（同组去重）。
- **R-4.4 协击**：`normal_attack.kind=coordinated` 出手前挂"协击"角标，走 Melee。
- **R-4.5 犹豫延迟**：`skill_trigger.kind=delayed` 组补"延迟"飘字 + 短停顿后
  静默落账（台词已由 TraitLine 前置弹出）。

## 五、机制表现要求（与领域账本）

- **R-5.1 势能**：客户端只维护"镜像账本"（服务端 `momentum_change` 权威）；
  `round_start` 全体四轨清零与服务端静默清零同步（计数单元＝回合）；
  势能火/金光环一旦点着持续到本回合结束；四轨迷你条（已取消展示）+ 满档流光 +
  跨档白闪 + 势能火分档为纯表现。
- **R-5.2 cut-in 触发源**：满档（服务 `cut_in=true` 且该轨镜像已 ≥5 时的下一次
  同轨进账，标题=即将造成伤害的技能中文名）、巨伤「重创」（组内单条
  damage > 3000 且未被格挡/反弹）、行动窗第 5 次追击、
  战术变更（无主体 → 文字横幅回退）。优先级满档>巨伤>追击，同一 group 只播一次。
- **R-5.2b cut-in 统一形状**：一切有主体的 cut-in 都是**独占播放单元**，形状与
  单挑同构——**推镜 → 横幅 → 本组出手命中（在近机位）→ 撤镜**；单挑是唯一在
  横幅拍额外飞立绘的特例。判据在**编译期**由 `Events/CutInPlanner` 逐组注记
  （2026-07-27 起，含势能预演；运行期只读 `EventGroup.CutIn`），禁止播放期
  推断或事后补切：那样既做不到伤害前推镜，暗幕还会盖住同帧命中特效（P-72）。
  相机唯一写方 `StageCameraRig`，中断路径必须还位。权威
  [cutin_stage.md](cutin_stage.md) + [playback_script.md](playback_script.md)。
- **R-5.3 状态表现**：状态施加/移除走统一落账（图标增删 + 光环挂卸 + 飘字 +
  音效同帧去重）；硬控/冥火用卡顶外侧抖动图标（先攻/犹豫不展示图标）；
  石化 = 灰阶渐变 + 冻结呼吸。
- **R-5.4 阵亡**：变灰倒下保留尸位；主将阵亡横幅强调；阵亡单位对后续演出
  一律跳过（不突进、不受击、不挂标）。
- **R-5.5 BGM 分层**：按全局势能三档 stem 淡入淡出、小节边界切层；单挑与
  cut-in duck；stem 缺失回退单曲，全缺静默。
- **R-5.6 高光选窗**：观感分 = 窗内伤害 + 满势能 cut_in × 3000；选窗为纯函数。
- **R-5.7 结算表**：终局技能杀伤/治疗统计沿 parent 因果链归因；status_tick
  归因停在状态（经注册表映射到来源战法），零重算。

## 六、资源与呈现

- **R-6.1 占位三级回退**：`Resources/ClientBattle/<类别>/<key>` 有则用；无则
  程序化占位（色块/合成音）；任何 key 任何时刻必能播出。
- **R-6.2 预热前置**：VFX 离屏实渲预热 + 按战报内容预生成字形/图标/音效/气泡；
  战斗热路径零首次开销。
- **R-6.3 池化与生命周期**：特效实例全部经池借还；出池必须复位缩放/旋转、
  重播粒子（兼容 playOnAwake=false 源）、保证 sorting 不低于池默认档
  （防被卡面盖住）；入池前必须停掉挂在实例上的 tween 与粒子。
- **R-6.4 缩放红线**：演出层只允许相对缩放（`*=`），禁止覆盖 localScale；
  variant 根缩放目视校准，登记于 assets_upload_guide。
- **R-6.5 sorting**：遵守 rendering_layout.md 层级总表；新表现先登记再实现。
- **R-6.6 机型适配**：取景唯一权威 CameraFitter；OnGUI 按屏高缩放；
  禁止写死 orthoSize/像素坐标。

## 七、鲁棒性要求（重构新增，历史 bug 反推）

- **R-7.1 tween 所有权**：每一个播放期 tween 必须有明确宿主并
  `SetLink(宿主 GO)`；宿主销毁/回池自动终止。禁止依赖全局 `DOTween.KillAll`
  作为正常清理手段（只允许作为 Stopping 的最后兜底）。
- **R-7.2 协程宿主**：播放期协程只允许两类宿主——编排器（主时间轴）与
  基础设施服务（池回收/预热）；单位级动画禁止游离协程（改用状态驱动或
  tween，以便硬停止可达）。
- **R-7.3 会话态集中**：一次播放的全部可变状态（镜像账本、去重记录、
  上下文、节奏标志）归属一个"会话"对象，Stopping/重建时整体丢弃；
  禁止靠散落 static 字段 + 多处 ClearAll 拼凑一致性。
- **R-7.4 单一落账入口**：任何事件对视图镜像的写入必须经唯一落账服务；
  演出层的伤害/治疗结算 = 表现（特效/飘字/顿挫）+ 调用该服务，
  不得自行改兵力/状态（消除双路径漂移）。
- **R-7.5 空引用免疫**：目标/施法者单位可能已阵亡或被 Teardown 销毁；
  演出与落账全路径 null-safe，缺失即跳过该表现、不抛异常、不中断时间轴。
- **R-7.6 配置外置**：演出策略数据（模板/资源 key/阈值/节奏默认值）以
  ScriptableObject 资产为唯一权威源；代码内置默认仅作缺资产兜底且
  必须与资产字段一一对应。
- **R-7.7 新机制接入面**：新增战法/状态的演出，只允许通过
  ① 配置条目（profile/注册表）② 新 Processor ③ 新 SkillPerformance 派生
  三个扩展点接入；禁止在编排器/落账服务里堆 if-else 特判。
- **R-7.8 文档同步**：任何行为条款变化，本文 + performance_mechanisms.md
  同步更新；文档与代码不同步视为任务未完成。

## 八、对服务端的依赖与适配建议（摘要）

播放侧当前自行推断的加工（借刀拆段、响应后置、集体合并、台词抽取、
模板推断、高伤/追伤 cut-in 阈值）依赖 group_id/parent_seq 语义稳定。
若后续按 [architecture.md §六](architecture.md) 的建议为战报增加
**加法式**播放标注字段（`playback_phase` / `segment_no` / `collective_key` /
`presentation` / `template_hint` 等），对应 Processor 可退化为直读标注；
在此之前本文 §二 的客户端加工规则为权威行为。

## 九、验收基线

1. Unity 编译零错误；`BattleReportTester` 播标准战报 + Manual 3v3 场景全流程
   （播放/重播/跳过/回配阵/高光/结算）无叠影、无残留、无异常。
2. 每类模板（普攻/群攻/逐段/远程/神谕/状态触发/单挑/纯治疗）肉眼各过一遍。
3. 独立版 60fps 无长帧（FrameSpikeProbe）。
4. 本文 R-条款逐条自查通过。
