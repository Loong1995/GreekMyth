# 项目总览与游戏世界观（定论）

## 一、项目一句话

希腊神话题材 **2D 卡牌对战手游**：服务器权威结算（Python `battle/`），
客户端（Unity `Assets/Scripts/ClientBattle/`）**只按事件流播放、零结算**。

## 二、核心玩法形态

- 3v3 卡牌对战（每队 1~3 人，主将必设）；系列连战最多 7 局，每局 1 准备回合 +
  正常回合默认打到一方主将阵亡（D-06 修订；安全兜底 `ROUNDS_PER_GAME=999`，
  `rounds_per_game` 可覆盖，演示/僵局测试用 8）；仅主将阵亡判负，平局残血续战。
- 兵力三池：可战 troops / 伤兵 wounded / 阵亡 dead；受击 30/70 拆分，
  治疗只回伤兵，回合始伤兵 30% 自然损耗。
- 战报 = 唯一事实源：后端 simulate 产出事件流 JSON（契约冻结），
  客户端播放、文本日志、客服重放全部由同一份战报驱动。

## 四、属性术语（定论，全项目统一，见 v0_analysis §四）

| 字段 | 中文 | 英文显示 | 用途 |
|---|---|---|---|
| `force` | 武力 | Might | 兵刃（physical）伤害攻方属性；单挑判定 |
| `intelligence` | 智力 | Hex | 谋略（magic）伤害与治疗**同用此字段** |
| `command` | 统率 | Guard | 兵刃/谋略伤害的防御属性 |
| `speed` | 敏捷 | Speed | 行动顺序 |

四维即此四字段，禁止新增第五维或改语义。四维 = 基础 + 成长 ×（等级-1）。

## 五、每武将三件套

1. **性格 trait**（`battle/traits.py`）：一条强制修正机制 + 台词
   （`trait_trigger` 事件确定性轮换，客户端弹气泡）。
2. **自带战法**：主将位神谕（is_oracle，r=0 释放并触发副将连携）或被动/主动。
3. **拆解战法**：可拆下装给别人（技能池见 `docs/skills/`）。

叙事／商业台词权威（传记·羁绊·登场／单挑／连携／击杀等）：
[`docs/character.md`](../character.md)（总则）+ `docs/character/` 分册。

## 六、风格红线（客户端）

- 横屏，卡牌上下布局（敌上我下），中央演出通道。
- 数值不缩略（-1300 不写 -1.3k）；兵力恒取事件 `troops_after`。
- 阵营配色为卡牌/特效基调（见 `docs/client/faction_style.md`）。
- 台词/机制文案一律中文，代码标识符一律英文。

## 七、框架级要求（做计划方案与写代码都必须对照的硬约束）

任何新计划（Phase 4 及以后）、新机制、新演出在提案与实现两个阶段都要
逐条核对本节；违背任意一条的方案不予采纳。

### 1. 多机型多分辨率兼容（红线）

- 目标设备：中低端安卓手机为基线（含 16:9 ~ 21:9 各比例、平板 4:3）；
  同一战报在任何分辨率下必须完整可读（六卡+血条+飘字+气泡不裁切不重叠）。
- 取景唯一权威 `CameraFitter`（保安全区半宽 4.6/半高 5.2，热切换每帧跟随）；
  表现层禁止写死 orthographicSize/像素坐标；UI 按屏高比例缩放。
- 新增任何画面元素必须在极端比例（4:3 与 21:9）下自查后才算完成。

### 2. 性能与体验（红线）

- 中低端机 60fps、战斗热路径零首次开销（预热前置）、Update/OnGUI 零 alloc、
  贴图压缩上限 1024；性能结论以独立 Build 探针数据为准。
- 零死帧：画面永远有活物（待机呼吸/光环常驻）；节奏由 duration 与
  ActionPause/GroupPause 控制，禁止静帧垫时间（单挑横幅唯一例外）。

### 3. 商业卖点方向（设计与演出投入的优先序）

1. **演出爽感是第一卖点**：单挑（每系列唯一、独立预算 ≤4s）、大招/神谕、
   暴击追伤、群攻齐发是核心爽点，演出资源与打磨优先投向这些点。
2. **性格台词 = 角色 IP**：trait_trigger 台词是人设载体（傲慢贯穿、宙斯多情
   逐人定制台词），新英雄必配性格+台词；台词质量按 IP 文案标准要求。
3. **希腊神话 IP 差异化**：阵营气质（奥林匹斯金/英雄红/海蓝/冥紫）贯穿卡面、特效、
   音乐；新内容不得稀释四阵营辨识度。
4. **付费点为资源换装而非数值**：立绘/卡框/特效皮肤走占位三级回退体系
   （上传同名资源即生效，零代码）——所有演出实现必须保持这条换装通道，
   这是皮肤商业化的技术前提。
5. **确定性重放是运营资产**：战报可逐字节重放（客服排查、精彩对局分享、
   赛事回放的基础），任何新机制不得破坏。

### 4. 长期可维护与可配置（红线）

- 数据驱动：数值/概率进配置常量，演出进 `PerformanceDatabase`/
  `UnitAuraService` 表，台词进 `traits.py`——新增内容改表不改主流程。
- 扩展走既定扩展点：后端=状态钩子+战法注册；客户端=Processor+
  SkillPerformance 派生。禁止在 engine/Runner 主循环塞特例。
- 契约只加法演进；新机制先问「现有事件类型能否表达」，不能再提新事件。
- 每个方案文档必须含：兼容影响（分辨率/低端机）、契约影响（是否升 schema）、
  资源需求（占位方案+正式资源清单）、回滚方式。
