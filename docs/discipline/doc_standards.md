# 文档规范

## 一、目录职责（新文档必须落对格子）


| 目录                 | 职责                         | 性质             |
| ------------------ | -------------------------- | -------------- |
| `docs/discipline/` | 不可违背的规范与全局规则（本目录）          | 常青，加法演进        |
| `docs/schema/`     | 事件流契约三件套                   | 冻结，加法演进        |
| `docs/mechanics/`  | 机制细则，index.md + 每机制一文件     | 常青，与代码强同步      |
| `docs/skills/`     | 战法三段式（效果/实现/事件流），按阵营分文件    | 常青，与代码强同步      |
| `docs/client/`     | 客户端框架/机制/资源/风格             | 常青，与代码强同步      |
| `docs/character.md` + `docs/character/` | 角色传记／羁绊／台词本（叙事，不改结算） | 常青；总则+分册 |
| `docs/dev/`        | 决策记录 / changelog / 分析与计划存档 | 决策与日志常青，其余历史存档 |
| `docs/prompts/`    | 任务书原文                      | 只读存档，禁改        |




## 二、硬性规则

1. **每文档 ≤500 行**（2026-07-15 人工修订，原 300 行）；超出必须拆分并在
   对应 index 登记。
2. 新建文档必须在其目录 index（或本表）登记；孤儿文档视为不存在。
3. **代码与文档强同步**：改机制/参数/类名而不改对应文档 = 任务未完成。
  常同步对：`roster.py`↔skills 文档、`names.py`↔`ChineseNames.cs`、
   `version.py`↔schema 文档、代码常量↔机制文档数值。
4. 历史存档文档必须在**文件头部**显式标注【历史文档/历史快照】+ 指向现行权威
  （2026-07-15 全量校阅确立，勿再出现「现状」写的是旧状态的文档）。
5. 数值写入文档时给出代码出处（文件+常量名），便于校阅比对。
6. 每个工作会话结束追加 `docs/dev/changelog.md`：日期 + 3-5 行
  （做了什么/改了哪些文件/为什么）。



## 三、写作风格

- 精要优先：机制文档每条 2-4 句 + 链接细则；不复制代码，引用文件与符号名。
- 表格用于可枚举事实；判定顺序/公式必须逐步写明，不许含糊「大概/左右」。
- 概率/系数一律写百分比并注明 bps 值；伤害/治疗写明乘区归属。
- 交叉引用用相对路径 markdown 链接；引用章节号要与目标文档实际章节核对。
- 「随机」一词只用于均匀随机；受击率加权选人必须写「受击率选人」。



## 四、校阅义务

- 大版本（schema/core 升版）后做一次全量文档校阅（如 2026-07-15 本次）。
- 校阅发现的不一致：文档错则改文档；代码与标杆语义不符则改代码——
以 `docs/skills/` 描述与人工决策（decisions.md D 系列）为语义权威。
